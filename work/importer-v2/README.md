# Steam Collection Organizer

本地 Steam 收藏整理工具 v2.3.2，提供中文收藏树、未分类入口、发行厂商筛选、最后游玩时间和时长、独立审核窗口、历史备份、JSON 导入导出、中国区商店资料缓存、免费许可证批量移除和 OpenAI 兼容接口。支持 Windows x64、Windows ARM64 和 macOS Apple Silicon。

v2.3.2 修复：免费许可证移除的“国区仍可获取”校验原先每款调用一次 `store.steampowered.com/api/appdetails`，批量执行时该域名很快对整机返回 HTTP 403，导致整批判为不合格、无法完成批量移除。现改为一款按 50 个调用 `IStoreBrowseService/GetItems`（`api.steampowered.com`，不受该限流影响），判定语义不变：`success != 1` 视为无公开报价或已下架，`is_free` 决定免费，主报价决定现价，仅 `type == 0`（game）算主体游戏。批量失败时全部标记为未核实并跳过，不猜测。

v2.3.1 修复：快照中不再需要的静态收藏即使原本为空，也会在应用时删除；删除前同时核对名称和成员。动态 / 系统收藏不删除，快照范围外的成员保留。

## 使用流程

1. 解压整个工具文件夹后打开程序，自动尝试读取当前 Steam 账号的游戏库及收藏。首页展示实际数据，程序不内嵌或自动加载个人清单。
2. 首次连接通常需要开启 Steam 的本机 CEF 调试接口。若显示未连接，退出正在运行的游戏，点击“准备连接 Steam”；工具会正常重启 Steam，等待库载入并自动刷新界面。之后也可点击“重新读取 Steam”。启动工具本身不会自动重启 Steam。
3. 选择 AI 整理，或在“历史 / 导入导出”里导入 JSON。两种结果都在独立审核窗口显示收藏树和游戏表格；可以搜索、勾选游戏、调整目标或输入新的静态收藏名称。导入和生成时主表保持原样。
4. 在审核窗口点击“接受并载入主表”，将草稿载入“待保存方案”。这一步仍不写入 Steam。
5. 生成预览，检查账号、库匹配、目标和变更数量，再点击“确认保存到 Steam”。工具重新核对状态，自动保存备份，并在写入后核对成员。预览后库状态改变时需要重新预览。

工具由单个可执行程序启动，界面在默认浏览器打开，本地服务仅监听 `127.0.0.1`。macOS 包是一个 `.app`；Windows 包含对应架构的 `.exe`，不需要安装 Go、Python 或 Node。

## 动态收藏

动态收藏的名称、数量、标签、筛选条件都由用户在 Steam 中创建维护。工具读取所有现有动态收藏及其成员，允许它们与静态收藏重叠；正常整理和快照导入不会创建、改名、转换或修改动态收藏。没有动态收藏也能整理。

旧版分类 JSON 的 `overlays` 字段可以导入，但不再要求对应名称或过滤器存在。若静态目标与 Steam 中现有动态收藏重名，预览会要求调整静态名称。导入快照中的动态规则保留为只读资料，不会据此新建动态收藏。

## 历史与恢复

“历史 / 导入导出”集中提供：

- 仅在实际应用收藏修改之前自动保存一份当前收藏快照。读取、重新连接、导入、AI 生成、接受草稿、编辑、预览、普通导出和无变更保存均不增加历史。
- 外置个人清单可作为 `history/` 中的普通记录提供，可导入、导出或删除；程序不内嵌个人清单，不会自动套用或重新生成它。实际范围以导入文件为准。
- 当前分类 JSON、游戏列表、完整库及收藏的导出，以及每条历史独立的“导出 JSON”和“删除”。

点击历史条目会在独立窗口审核。导入 `collections.json`、完整库导出或当前收藏 JSON，可以恢复原来多个静态收藏的成员关系；导入普通分类规则则按每款一个静态目标处理。快照是其 AppID 范围内的完整目标状态，省略的静态收藏会移出范围内成员，清空后删除，包括原本为空的静态收藏。原快照不包含的新游戏保留现有成员关系。快照属于其他账号时禁止写入。手动调整只改选中游戏的静态目标，其他游戏保留原来的多个静态归属，动态收藏保持当前 Steam 状态。“未分类”是无静态目标的状态，不会创建一个冒充 Steam 系统未分类的静态收藏。

历史默认保存在工具同目录的 `history/`：Windows 为 EXE 旁，macOS 为 `.app` 旁（不在 App 包内部）。价格缓存、导出和执行备份也保存在工具旁。移动工具时请一起移动这些目录。可用 `-data-dir` 指定其他数据目录；目录需要可写，请先解压再运行。删除历史不修改 Steam，也不删除独立的执行备份，清单不会在重启后恢复。旧版系统用户配置目录中的历史不会自动移动，可手动将记录文件夹复制到新 `history/` 下。

## AI

填写 OpenAI 兼容的 Chat Completions 服务地址和密钥，再获取模型。支持以 `/v1` 结尾的地址；自定义其他接口前缀请直接填完整路径（程序只在无路径时补 `/v1`）。提示词由用户输入，输入框提供参考，程序不自动沿用本次个人分类要求。AI 可按用户要求提出新的静态收藏名称；分类标记保留。返回值只用于草稿，不会自动写入 Steam。

AI 服务收到批次内的名称、AppID、分类标记、厂商、已缓存价格及游玩资料。密钥仅存在运行期间的内存，不写入文件、历史或报告。个人分类规则不写入通用程序逻辑。

## 库浏览与商店资料

“未分类”对应当前 Steam 系统未分类；“无静态收藏”也包括仅位于动态收藏的应用。待保存方案按新静态归属计算两种视图。表格支持发行厂商筛选、名称/厂商搜索、最后游玩和时长排序、跨页勾选。时长来自 Steam 的 `minutes_playtime_forever`，只用于显示；是否玩过仍按最后游玩记录判断。旧文件缺少时长时显示“未提供”，重新读取 Steam 可补齐。

“获取商店资料和价格”调用中国区 Steam `appdetails`，缓存发行商、开发商、应用类型、价格、免费状态和查询时间到工具旁的 `prices.json`，每次最多 500 款。缓存时间以实际条目为准。锁区、下架或失败显示待核实，不把接口无返回直接认定为全球绝版。

## 勾选免费游戏并批量移除

在列表勾选游戏（跨页保留），点击“移除选中的免费游戏”。每批最多 50 款，先弹窗逐项显示可移除/跳过及原因，再由用户确认。工具再次读取当前账号、最后游玩和中国区实时商店资料，并通过 Steam 原生 `bFreeRemovableLicense` 检查许可证。收费、免费标记与付费报价冲突、锁区/下架、已游玩、保护标记、大作试玩/性能测试、从属内容和未知状态均跳过。没有通过检查的条目时不启用确认按钮。

执行调用 Steam 自己使用的 `UserAccount.CancelLicenseForApp`，按 AppID 移除免费许可证；不传猜测的包 ID，不调用卸载向导，不编辑动态收藏。确认只可使用一次且五分钟过期。确认后若状态变化，本批停止；执行中失败或回复丢失，停止后续条目并显示已完成和结果不明的项目。请重新读取 Steam 核实，不要盲目重复。操作日志保存在 `removals/`，它与收藏历史分开，不能恢复许可证。当前免费状态无法保证未来仍免费或不下架。

此功能已验证原生许可证只读识别及模拟执行、保护、状态变化和中断处理；没有对用户真实游戏执行移除测试。

## 连接诊断与验证范围

点击“连接诊断”检查实际 Steam 安装路径、进程、当前账号、调试连接、游戏库及收藏读取、历史目录写入权限。诊断不修改 Steam 收藏。原 GUI“一键自测”已移除；开发用合成规则检查仍可通过命令行 `-self-test` 运行，与个人清单无关。源码测试还覆盖 macOS AutoLogin/MostRecent 登录格式、账号歧义、便携历史路径、任意动态收藏保持、收藏快照导入、多静态归属恢复、账号不匹配、历史删除、重复执行、备份恢复和旧格式兼容。

Windows 账号识别继续使用原来的注册表 ActiveUser 逻辑，用户已反馈 Windows 基本功能可用；本次保留该实现。macOS 登录识别兼容 AutoLogin 和 MostRecent，多个账号无法唯一识别时停止。三个目标二进制均交叉构建，自动写入测试使用模拟 Steam 接口；真实收藏写入和云同步未在本次验证。Steam 更新可能使内部接口不可用，连接或预检失败时程序会停止。

当前 Mac 已实测读取 6,576 个应用、156 个收藏及连接诊断。macOS 的“准备连接 Steam”重启流程仍有未完成验证的问题，本次按用户要求暂停排查；不能把该流程视为已修复。

## 文件与构建

- `history/`：工具同目录的可管理历史；外部方案可以手动复制相应记录到这里。
- 独立方案包中的 `classification.json`、HTML、逐项依据等不属于程序内置数据。
- 源码目录 `classification.json` 是旧的个人回归测试夹具，程序不自动加载它；公开发布前应替换为匿名夹具。
- Go/JavaScript 完整源码和 vendored 依赖使用 MIT License，第三方依赖见 `THIRD_PARTY.md`。

需要 Go 1.23 或更新版本：

```sh
go test -mod=vendor ./...
node --test bridge_test.mjs
GOOS=windows GOARCH=amd64 go build -mod=vendor -o SteamCollectionImporter.exe .
GOOS=windows GOARCH=arm64 go build -mod=vendor -o SteamCollectionImporter-arm64.exe .
GOOS=darwin GOARCH=arm64 go build -mod=vendor -o SteamCollectionImporter .
```

`collection_order` 控制工具里的方案显示顺序和创建处理顺序。Steam 自身的字母排序由客户端决定，工具不会修改 Steam 的排序实现。
